# 伙伴跟随与骑乘

更新：2026-10-07。本文描述当前实现，取代此前“水系仅水面骑乘”和 15 条人工白名单规则。对战 AI 不在本轮范围。

## 已采用的玩法要求

- 跟随与骑乘各占一个独立名额，可以同时启用，不能是同一个队伍个体；同种不同个体允许。换位、入库、保存及读取维护个体选择。
- 跟随沿实际地面路径移动，转弯不斜穿墙，换地图清除旧路径；未满足安全落点和净空时暂不显示。
- 飞行骑乘暂时没有高度、升降、飞越或越障机制。原生振翅只是画面动画，所有坐骑使用同一逐格碰撞路径。
- 骑乘与冲浪是两种能力。水属性不禁止陆地骑乘，骑上水系或飞行系也不授予水面通行权限。
- 操作菜单按状态显示“跟随”或“收回”、“骑乘”或“下骑”；不满足资格、体力、场所、净空或个体条件时不出现“骑乘”。

## 覆盖全基础物种的规则

`tools/build_travel_profiles.py` 校验已固定版本的 PokeAPI CSV 哈希，读取 1,025 个默认物种的体型分类及身高、体重，生成 `content/travel/generated/profiles.json` 和共享 C 表。该表是 **Omni 玩法设计，不是官方载重认证**。

1. 初筛要求身高至少 1.0 m、体重至少 30 kg。这是可调整的游戏阈值，不是主角体重推断。
2. 默认承载结构只接受鳍状、四足、单对翅膀、多对翅膀及多足结构类别；直立类、人形、无定形、集合体、只有头部等不会仅凭体重通过。蛇形的总长度不作为背部宽度，必须明确例外。
3. `content/travel/anatomy-overrides.json` 记录结构和接触安全例外及理由，例如喷火龙、快龙、大岩蛇、暴鲤龙和两只帕底亚坐骑；坚果哑铃、万针鱼等全身尖刺对象拒绝乘坐。火焰马的接触安全是明确的 Omni 设计假定。
4. `omni_travel_eligible` 只判身体条件；`omni_travel_access` 另判地图及权限；素材准备情况不改变身体资格。所有合格物种都允许地面表现，包括拉普拉斯、暴鲤龙等水系。
5. 室内禁骑。大岩蛇等宽体对象要求更大净空；适配器检查当前位置和目的格周边实际碰撞及人物占用。当前为两侧净空近似，**尚不是任意大小的完整身体足迹或转弯扫掠碰撞**。
6. 水面必须显式提供独立的 `OMNI_TRAVEL_PERMISSION_SURF`。当前地图仍未接入水面行走／上下岸，适配器不授予该权限。核心中的权限测试不能当成水上玩法已完成。

当前规则产生 **179 个可骑乘物种**，全部接入同一场景骑乘状态。其余物种有确定的拒绝分类；这不表示全部分类已经逐只完成最终解剖／设定审查。替代形态、性别差异、异色、Mega、极巨及羁绊形态没有自动继承这份默认形态结论，仍待分别审查。

## 可玩入口与控制

[随行与骑乘试用](http://127.0.0.1:4173/play?travel) 的初始队伍仍是皮卡丘、妙蛙种子、独角犀牛、风速狗、肯泰罗、拉普拉斯，皮卡丘默认跟随。

- 场地中 `L` 收放跟随伙伴，`R` 上下骑已选坐骑。
- `START → 宝可梦 → A` 打开按状态变化的动作菜单。队伍页 `R` 切换跟随，`START` 切换骑乘。
- **试用场地中 SELECT + R / SELECT + L** 在全部 179 个坐骑之间向后／向前切换，替换第六个队伍个体并尝试骑乘；狭窄或室内位置仍拒绝。此组合不改变普通冒险操作。
- 原生模拟器在封面按 `START + SELECT` 进入同一试用。
- 试用不写 SRAM，不配置故事捕获点、不授予冒险进度。新加入的物种只有参考基础数值供试用队伍显示，没有虚构正式招式表；其特性／招式面板不是完整战斗实现。

## 素材与美术状态

场地已编入 189 个基础物种，包含 179 个坐骑及已有／保留的跟随对象。四方向源图和原生队伍图标来自固定版本 `rh-hideout/pokeemerald-expansion`，URL 与 SHA256 记录在 `assets/source/travel-roster.json` 和 `travel-sprites.json`。已有 12 种队伍图标继续使用 Rocket 原素材，其余使用原生 icon，不拿战斗图片缩小充当图标。

六帧图按下、上、左读取，右向依来源镜像；八帧图使用独立右向帧，遵循来源 `sAnimTable_Following_Asym`。共同画布和定位保持原像素比例；不缩放、不平滑。调色板和连续同色像素无损压缩，镜像帧共享存储，构建时逐像素往返比对。当前包含完整骑手坐姿、场景帧与队伍图标的资源为 **398,924 字节**，可放入 32 MB GBA ROM。队伍图标暂显示源图第一帧。

所有允许骑乘的物种都要求四向各有两张不同的原生姿态；不能用两个相同帧索引冒充步态。保留的坚果哑铃源图为静态，不计为骑乘动画通过。

骑手改用同一份究极绿宝石 IV 小智 ROM 中的完整原生 32×32 坐姿，与当前行走素材同为 XY 服装。保留手臂与弯曲双腿，不裁切站立上身、不缩放或重绘脸部；右向遵循原引擎镜像。来源槽位与像素哈希见 `assets/source/ash-iv-seated.json`。该坐姿来自冲浪图形槽位，复用画面不授予冲浪能力。

`assets/characters/riding-layouts.json` 保存每个物种四向、两帧的原像素座位与前景遮挡。179 只当前合格坐骑均已在实际 ROM 中检查；振翅步态间的座位位移限制在各轴 2 像素以内。拉普拉斯、暴鲤龙侧面落在背部；帝牙卢卡、冰雪巨龙、猛雷鼓等长颈对象由原生颈部像素遮挡骑手。上下骑使用四个呈现时刻连接完整站姿与坐姿，地图位置及高度不变。它是共享原生坐姿加逐物种配置，并非为每只坐骑重画独立握持动作，也不是 3D 骨骼模型。

完整 179 × 4 × 2 实机画面已逐页检查。复现使用 `tools/render_travel_roster_review.py`；六物种对照和上下骑动图使用 `tools/render_riding_art_review.py`，后者动图放慢供检查，不代表实际速度。验证绑定的 ROM 与布局哈希见 `docs/assets/riding-art-verification.json`。

## 验证与边界

- `tests/core/test_travel.c` 遍历 1,025 条记录，验证身体判定、室内限制、水面必须独立解锁、净空、速度及跟随路径；明确检查大比鸟、拉普拉斯、暴鲤龙及尖刺例外。
- `tests/travel-roster-rom.cjs` 在实际 ARM ROM 中经按键逐只切换全部可骑乘物种，检查骑乘状态、四方向的两帧索引、独立跟随、存档不变，并检查大比鸟无法穿过实际地图障碍。
- `tests/travel-rom.cjs` 对独角犀牛、风速狗、肯泰罗、拉普拉斯检查真实位移及加速。当前同一路段步行 19 帧、骑乘 8–9 帧；渲染耗时不等于逻辑速度倍数。
- `tests/rider-art-rom.cjs` 检查上下骑中间帧、最终骑乘状态、位置和 SRAM 不变。
- `tests/party-actions-rom.cjs` 检查单一动作标签、不可骑乘时隐藏按钮、五／六行菜单映射、室内拒绝及拉普拉斯陆地上下骑。
- `tests/initialization-rom.cjs` 继续检查正常开场、两种小茂战结果、礼物、包裹、保存继续、跟随持久化和坏档回退。
- `tools/render_travel_roster_review.py` 从实际 ROM 帧生成全物种四向对照及飞行／水系示例动图。验证摘要保存于 `docs/assets/travel-verification.json`；ROM 和截图留在本地 `build/pallet/`。

Adventure 存档仍为 v6、916 字节。当前并未完成全物种跟随、完整水面／上下岸、全形态资产、全物种战斗正背面运行时接入。完整资产覆盖统计由 `tools/audit_species_assets.py` 生成，须分别读取场地、战斗、队伍和图鉴状态。
