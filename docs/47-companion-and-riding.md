# 伙伴跟随与骑乘

2026-10-01：用户将这两项确认为版本核心 feature，并要求直接制作可玩版本，逐步补齐全物种与地形支持。

## 已采用的玩法要求

- 队伍中的任意宝可梦都应可指定为随行伙伴；同时只放出一只，切换时替换旧伙伴。2026-10-05 更正：骑乘使用另一个独立名额，允许一只跟随、另一只骑乘；不能是同一个体，同种不同个体允许。
- 随行选择与战斗领队分开。更换领队或队伍顺序不应换掉已经选中的个体；存入电脑时正确收回／重排索引。
- 跟随沿主角刚走过的实际路径进行，转弯不斜穿墙，脚步有方向动画；换地图时旧路径作废，等待安全位置重新跟上。
- 地形能力与元素属性分开：水属性不自动等于能够载人游泳，飞行属性不自动赋予玩家越过障碍或飞行权限。
- 骑乘资格由体型、承载结构、接触安全、移动介质和当前空间共同决定。骑乘像自行车一样加快移动，但仍逐格检查碰撞，不因加速穿墙或跳过剧情门槛。

## 骑乘判断规则

共享实现位于 `core/src/travel.c`，GBA 不单独硬编码“某几个编号可骑”。物种能力表提供身体条件，同一函数计算准入或拒绝原因。

1. **承载体型**：体型须达到中等或大型。这里衡量可用身体宽度和承载体量，不能把长尾、角、翅展或蛇形全长当作可坐的背部。小型初期伙伴不满足条件。
2. **承载部位**：有稳定的背部或宽甲壳；不能仅因为重、长或战斗攻击力高就通过。
3. **接触安全**：乘坐部位可安全接触。持续伤人的尖刺、毒液或不可控热源不能默认忽略；物种可控制的火焰等情况须在能力表明确核定。
4. **介质匹配**：陆行坐骑在地面通行，水行坐骑在水面通行。当前核心给独角犀牛／烈焰马登记陆行，大岩蛇登记大型陆行，拉普拉斯／暴鲤龙登记大型水行；后几项是能力规则记录，不代表素材和地图玩法已经完成。
5. **空间与场所**：室内禁骑；大型身体要求更宽的通道。不能把大体型素材缩小来绕过空间限制。未核定的物种可纳入跟随扩展，但骑乘默认拒绝并说明“尚未核定”。

这些是 Omni 玩法分类，不冒称官方逐物种载重数据。当前规则没有编造主角体重、年龄或生理变化；将来年龄阶段／体型变化需要新的承载评估。

## 当前可玩范围

普通冒险的八种已支持伙伴都接入随行素材：妙蛙种子、小火龙、杰尼龟、皮卡丘、波波、小拉达、瓦斯弹、独角虫。独立试用包含独角犀牛、风速狗、肯泰罗三只陆地坐骑，另有拉普拉斯的陆地拒绝样例；共 12 套场地素材。未给正式故事新增捕获点、礼物或租借事件。

- 队伍页：上下选伙伴、左右切换列，`A` 打开操作菜单；查看能力、交换、跟随／收回、骑乘／下骑、图鉴、取消。`R` 随行及 `START` 骑乘仍有快捷键。
- 探索：`L` 收回／放出随行伙伴；`R` 对已选择的坐骑上下骑。无坐骑选择时提示先在队伍中选择，不能默认拿随行对象骑乘。
- 网页 [随行与骑乘试用](http://127.0.0.1:4173/play?travel)：默认皮卡丘随行。`START → 宝可梦 → 下两次 → START` 骑乘独角犀牛，皮卡丘继续跟随。也可用 A 菜单选择骑乘。
- 原生模拟器在封面同时按 `START + SELECT` 进入同一试用。试用不写 SRAM；重新加载普通游戏恢复正常冒险。

平路逻辑速度为步行 2、跑步 4、骑乘 8 单位／模拟步；草地骑乘降为 4。实际画面还受绘制耗时影响，不能把逻辑倍数声称为实测帧率倍数。当前实际 ROM 同一路段单格测得步行 19、骑乘 7 个硬件帧。脚步帧按行进距离切换，避免骑乘加速后腿仍按原来的时间频率慢走。

| 情况 | 当前行为与完成程度 |
|---|---|
| 普通陆地、转弯 | 已接入主角路径跟随及方向步态，玩家不会被自己的伙伴卡住 |
| 草地 | 遮挡沿用地图遮罩；骑乘降速；仍保留正常冒险原有遇敌流程 |
| 门口、相邻地图、楼层切换 | 旧跟随路径作废；进入门口先下骑，下一次安全移动后重新跟上 |
| 室内 | 可以随行，禁止骑乘；放出时避开人物、阻挡格和门口，无位置则等安全移动 |
| 剧情演出 | 暂收地图伙伴并下骑，保留选择；恢复控制后重新跟随 |
| 失去战斗能力／存入电脑 | 失去战斗能力时不显示、不允许新放出；存入电脑清除该随行选择 |
| 水面 | 核心已有介质准入测试；当前地图水面仍阻挡，未开放水上骑乘 |
| 桥上下层、跳崖、潜水、飞行、冰面、沙地 | 尚未实装专门适配，不能因为陆地测试通过就声称完成 |
| 大体型窄通道 | 核心已有净空拒绝规则；当前可玩样例为一格承载体型，大型足迹地图检测仍需补齐 |

## 美术与来源

目前 12 套素材来自固定版本 `rh-hideout/pokeemerald-expansion` 的 HGSS 风格原生跟随帧，来源及像素哈希在 [travel-sprites.json](../assets/source/travel-sprites.json)。每只六张源帧解码为四方向各两帧，右向按源引擎约定镜像；透明边界统一裁取，所有方向共用定位，原生像素不重采样。原始下载和编译资源只存在本地。

已在实际真新镇场景并排查看主角、皮卡丘、独角犀牛及家具／门比例。骑手当前是原生小智上身与坐骑的临时遮挡合成，**专用坐姿、握持动作和上下骑动画尚未完成**，不算最终人物美术。不同形态、性别、异色和后续世代的全物种覆盖仍待扩展。

连续截帧还发现原探索绘制会显示只画完背景的中间帧；本轮将地图、伙伴、主角和覆盖界面先合成为完整画面，再于 VBlank 转入显示，消除这些中间帧的人物闪烁。`tools/render_travel_review.py` 将实际 ROM 帧序列生成放慢检查的动图和四朝向对照。

## 操作菜单按当前状态显示

队伍操作菜单只显示当前可执行的单一动作：随行中显示“收回”，未随行显示“跟随”；正在骑乘所选个体时显示“下骑”，其余情况仅在准入通过时显示“骑乘”。准入复用共享规则，并检查体力、跟随个体冲突和当前地形；小体型、未核定、体力耗尽、室内、水陆不匹配或空间不足时，不生成“骑乘”这一行。快捷键仍保留防御性准入检查。

可见行号与动作 ID 分开，隐藏项目后“图鉴／取消”紧接前项，窗口高度与光标循环按实际项目数计算。`tests/party-actions-rom.cjs` 已通过实际 ROM 的跟随／收回、上下骑、可骑物种正在跟随时隐藏骑乘、小体型、拉普拉斯陆地、室内，以及五／六项光标循环和图鉴动作分派检查；截图逐张核对了按钮文字。`travel-rom` 和 `party-menu-rom` 回归通过，试用 SRAM 保持不变。
