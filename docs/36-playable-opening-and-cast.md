## 对话框与碰撞修正

之前只复用了通用九宫格边框，却使用自有细字库、蓝色姓名栏和 A 提示；这并不是来源的 field dialogue。现在 `tools/build_rocket_dialogue.py` 读取用户归档火箭队 ROM 的中文字形、源标点、对话边框、调色板及续页箭头，记录在 `assets/source/rocket-dialogue.json`。

以来源 ROM 正常开机、按 A 后的实际对白为参照：窗口 `(0,112,240,48)`，正文起点 `(16,121)`，两行间隔 14 像素，灰色笔画带浅色阴影，姓名在正文里。汉字编码参考 [Wokann 字库补丁项目锁定版本](https://github.com/Wokann/Pokemon_GBA_Font_Patch/tree/5a78e4da2cf61fbe7b7e64b110accc06cdee800b)，字形仍取本地 ROM，没有拿参考仓库的字体替换它。正文按像素宽度编排，为续页箭头留空。

此前走位只有起终点插值，前景遮挡不能阻止穿进花盆。现在地图编译器同时输出 blockdata 碰撞与地块行为；脚本检查所有站位和终点，将桌椅、花盆、设备及其他演员视为障碍，规划四方向路线。`core/src/stage.c` 在运行时逐像素检查脚下矩形，异常路线停在最后安全位置；GBA 适配负责渲染和人物朝向，深度排序按当前脚下位置计算。

`tests/opening-layout.py` 将源 ROM 的实际窗口、汉字、句号、阴影和两行基线与提取结果逐像素比较，再核对本作全部对白帧。另保留旧花盆格回归、桌面捷径、被占终点与角色路线检查。`tests/presentation-rom.cjs` 正常播放时逐帧采样脚下区域，同时检查三次会议切场未重启 BGM。

原生 240×160，整帧在 EWRAM 合成后于 VBlank 显示。玩家脚本单独编译，不导出编剧秘密。时序和移动逻辑在 portable C，图片、DMA 和寄存器属于 GBA adapter。其他菜单和普通探索的旧字库本轮未全面替换，不能把开场对齐声称为全游戏 UI 复刻。

封面按 A／B／START 进入存档菜单。“新的游戏”先播放开场，完成或确认跳过后才初始化新存档。已有存档仍先确认替换。标题 **L** 回放、**R** 人物画册，二者不写存档。序章 **A** 先显示全文、再继续；走位自动完成。**START** 打开跳过确认，**A** 跳过、**B** 继续。浏览器 Z 对应 A、X 对应 B、Enter 对应 START。

## 人物形象与档案

目前编入 **22 张 80×80 立绘**：上一轮讨论的 18 位劲敌／关联人物，以及小智、渡、坂木、大木。标题按 **R** 打开开发画册，左右翻页、B 返回。小智立绘也用于训练家卡。

小智、小茂、阿弘、优藤圣代、小明、真司与小银、阿杏、碧蓝、叶子、艾岚、彼特来自两组 imagegen 初版图集。它们经过裁切、缩采样和 RGB555 编译，属于游戏立绘草案，不能声称是官方像素素材、服饰逐帧核对成果或完整动画。提示词及输出保存在 `assets/characters/`。生成图实际带有透明通道；编译时将 alpha 转为 GBA 的透明标记。它们尚未作为完整战斗动画套件使用。

小进、步美、小驱、青绿、阿桔、小椿、赤红、大木、渡、坂木使用 [Showdown 训练家素材档案](https://play.pokemonshowdown.com/sprites/trainers/) 中的现成像素立绘。小进素材署名 **kyledove**，步美、小驱署名 **Brumirage**；其余所选游戏像素列明 Game Freak／Nintendo／Creatures 来源。遵守来源的作者署名与未经许可不编辑要求：不重新绘制、不缩放，保留原像素，只作透明填边及 GBA RGB555 编码。第三方源图在忽略目录，URL、哈希、署名与处理方式纳入 Git。

新图集与小智行走图集的另外两次生成遭服务拒绝，记录请求 ID；没有转用收费 API。**小智地图小人仍是明确标注的赤红占位，完整四向行走、投球、战斗背面、青年中年与 3D 模型尚未完成。** 立绘可用不等于这些套件完成。

当前序章十二位演员／群像／剧内声音均有档案与绑定，共保留 88 份人物记录。新增匿名宝可梦参战群像与前线无线电联络员，群像没有独立 NPC 实例或已命名个体。旧旁白、传令员、广播员标记为已撤下，常青乔伊仍用于正常探索。角色本场行动与长期生平分开，未知出生、空白历史和未来结局保持 `null`。人物生成图不充当动画设定考据。

## 经典音乐的来源和处理

上一版三首简单 PSG 编曲已移除。现在从用户归档的 `assets/imported/rocket-user/rocket-user-modifier.gba` 中调用原 m4a／MP2K 驱动，在 mGBA 离线渲染原来的音色、采样与混音，没有用系统 MIDI 音色重配。原文件只读，播放器补丁仅在忽略目录的临时副本里使用。

| 曲目 | 来源曲目槽 | 用途 |
|---|---:|---|
| 宝可梦塔 | 518 | 保留素材，当前序章未使用 |
| 真新镇 | 512 | 清晨与当前普通探索 |
| 训练家对战 | 509 | 战争开场前段与当前对战 |
| 冠军之路 | 507 | 保留素材，当前序章未使用 |
| 希尔弗公司 | 519 | 三场会议与祖孙会面的连续声桥 |
| 火箭队基地 | 486 | 保留素材，当前序章未使用 |
| 大木研究所 | 513 | 深夜研究与研究所探索 |
| 宝可梦中心 | 515 | 当前中心探索 |
| 确认音 | 5 / SE_SELECT | 按键确认，取代原来的蜂鸣音 |

八首 BGM 各声部的音高顺序与锁定火红 MIDI 数据对照通过。这是逐声部旋律核对，不声称所有原版音色字节完全相同，也不把改版曲目表的编号当作原版编号。确认音按来源引擎曲目槽核对，未冒充有完整 MIDI 比对。定位原驱动参考 [Saptapper](https://github.com/loveemu/saptapper/tree/ff7ec3e4da1f1ffc3bcc05793268036a319b4466)；本项目的提取、离线运行与编码程序在 `tools/audio/` 和 `tools/build_classic_audio.py`。

清单 `assets/source/classic-audio.json` 记录来源 ROM SHA-256、原引擎地址、源 MIDI URL 与哈希、旋律比对、循环位置、PCM 与编码哈希。音频本地保存。导入器会核验输入 ROM 和已锁定曲目，不在仓库分发商业游戏 ROM 或配乐文件。

为实际 GBA 容量和声音硬件，配乐转为单声道 16,384 Hz，每 256 采样一个独立 IMA ADPCM 块（132 字节），最后经 Direct Sound 8 位 DAC 播放。共 3,569,280 字节；八首 BGM 相对下采样 PCM 的编码 SNR 为 23.6–27.5 dB。这是有损的 GBA 适配，不能叫无损 CD 音质。短淡变用于换曲；循环点来自原驱动实测时钟，末端只有约 2 ms 的去点击处理。

Timer 0 提供采样率，Timer 1 每 256 采样补充缓冲；FIFO 双缓冲预留提前读取的 32 字节。ADPCM 解码在共享 C 核心；GBA 构建将解码与缓冲中断放入 1,424 字节 IWRAM，减少与界面绘制争用 CPU。Timer 2／3 保留 64 Hz 的独立演出与输入时钟。

探索中 **SELECT** 循环切换 **1／2／4 倍行走模拟速度**，BGM 与字幕保持原速。没有声称所有战斗动画已有倍速。任意第三方模拟器的外部快进依然需要模拟器音频协作；ROM 无法通用感知宿主墙钟，本轮也没有通用外部快进补丁。[GBA Direct Sound 硬件说明](https://gbadev.net/gbadoc/audio/directsound.html)

## 构建与验收

```powershell
./tools/build_pallet.ps1
node tests/presentation-rom.cjs
node tests/rocket-dialogue-reference.cjs
python -X utf8 tests/opening-layout.py
python tests/classic-audio.py
node tests/pallet-smoke.cjs
python tools/build_story_bible.py
python tools/build_story_bible.py --check
python tests/story_bible.py
node tests/story-bible-browser.cjs
node tests/presentation-browser.cjs
```

默认构建已改为封面 → 存档菜单，详见 [启动流程](38-title-and-save-menu.md)。`-StoryStart` 作为兼容参数等同默认，`-DebugDex` 才开机直接进入图鉴；网页直达 `/play?dex` 无需另一份 ROM。`-ReuseAssets` 要求所有改变的资源、脚本与字体已提前重新编译。本次先运行 `build_opening_stages.py`、`build_presentation_assets.py`、`build_rocket_dialogue.py`，再复用其新产物链接。编译需要本地归档 ROM、锁定素材、mGBA WASM 和 Zig；导入的来源资源、工具链与构建产物不提交 Git，生成原画与提示词提交。音频 Python 依赖版本见 `tools/audio/requirements.txt`；地图和图像构建另需 Pillow，本轮为 12.3.0。

验收报告分别写入 `build/pallet/presentation-test.json`、`story-presentation-test.json`、`audio-correlation.json`。音频测试从实际 ROM 连续录制一分钟，与来源混音比较九个窗口的波形和采样相位，覆盖 FIFO 多次回绕及音乐循环。相关性与节拍测试不能替代主观试听，更不能据此声称在 GBA 真机上测试过。

## 本轮实际结果

本次战争段替换后的实际结果与 ROM 哈希见 `build/pallet/build-report.json`、`presentation-test.json`、`opening-blocking-samples.json`。构建产物、来源 ROM 和截图不提交 Git。

- 六场／77 节拍正常按键与自动播放；43 次文字展开检查、12 次动作不可跳帧检查、跳过／取消、22 人画册、回放不改存档与新冒险交接。
- 全部走动镜头检查脚下矩形不进入家具、演员互不重叠；三次会议切场检查曲目、解码进度与循环计数，配乐持续。
- 来源实际运行画面与本作全部对白的像素核对；碰撞负例与共享 C 路径防护检查。
- 浏览器战争开场／画册／图鉴直达、存档保护；设定集生成、`--check` 和 49 项故事连续性检查通过。本次没有重跑完整冒险烟雾路线。
