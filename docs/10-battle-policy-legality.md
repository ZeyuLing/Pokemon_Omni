# 对战政策与合法性实现（2026-09-17）

本规格采用用户最新确认，替代早期四档难度、共享特殊机制额度、全局等级 50 与首领完全对称的草案。实现范围是平台无关的政策与验证核心，不是完整战斗引擎。

## 难度与等级

简单：无玩家等级上限；NPC 按剧情进度配置等级，不随玩家等级缩放；基础 AI；个体值按配置；性格与努力值按队伍角色配备。玩家战中背包及各机制次数不限。不限次数不等于跳过携带物、物种、当前状态和互斥条件，也不代表同一只宝可梦可重复叠加 Mega 属性。

困难：玩家受当前章节等级上限约束；中等公开信息 AI；NPC 默认 6V，性格努力值按策略配置；重要训练师至少有一只适用的羁绊伙伴。普通训练师队伍数量按剧情配置，不强制六只。

疯子：沿用困难，使用最高强度公开信息 AI；部分普通人也可拥有羁绊伙伴，未到适用进化阶段时不强行配备。白名单首领可拥有战外永久 Mega：可以携带普通物品、不花 Mega 次数、不能使用其他机制、玩家不可获得。这是公开的首领特权。

设 H 为随身队伍最高等级（包括未出场、濒死宝可梦，不包括蛋）；B 为每只 NPC 宝可梦自身的剧情基准、当前进度重赛等级以及适用道馆等级下限的最大值。困难及疯子下：H > B 时 L = min(100, H+1)，否则 L = B。H=B 不提升；不会随低等级玩家降级。100 级为边界，只能持平。需要低等级/低数值的战术必须显式标记例外，不能由 AI 暗改。简单只采用进度基准，不按 H 缩放。

一周目等级上限只由对应必需道馆首次获胜推进；重赛不重复推进。具体每章数值尚未由剧情定义，配置不虚构数值。跨地区共享进度需要章节表决定哪些道馆推进主线。

## 重赛与机制

路人首次视线遭遇自动开战，此后只在玩家交互并确认“是想再战斗一次吗？”后进入。所有路人无限重赛，每次重新计算当前进度等级。首次剧情奖励与重复奖励分表，防止刷徽章、解锁或唯一物品。遭遇标记应在实际成功进入战斗后提交，合法性阻断不能吞掉首次遭遇。

困难以上每方 Mega、Z、极巨化、太晶分别一次；互不扣除。羁绊也使用独立额度，一次为当前建议默认值，具体效果尚未冻结。简单玩家不限次数；简单 NPC 默认仍各一次，作为待调整的明确默认。机制效果、持续回合和同一只宝可梦跨机制兼容矩阵需在完整战斗系统实现；当前额度函数接收可信资格检查结果，不能直接相信 UI 传来的布尔值。

困难以上禁止训练师战中背包恢复及战斗强化道具，携带物正常生效。没有提前报下一只和免费询问换人；正常回合换人允许。野生捕获走单独流程。AI 不能读取玩家已提交动作、未公开招式/道具或未来随机数。检查队伍的验证器有权读取数据，但不得把这些信息传给 AI。

## 合法性分层

1. 存档/导入适配器先检查版本、长度、整数与范围，再转成 C 的有限宽度字段；不能先截断溢出数据再验证。检查和与备份用于损坏恢复，不是无法伪造的作弊证明。
2. 所有难度检查结构：等级 1–100、IV 0–31、现代规则 EV 单项 ≤252 且总和 ≤510、性格/物种/物品/特性存在、招式不重复、PP/PP Up 合法。能力实数由种族值等重新计算，不能相信存档里被修改的最终能力值。
3. 招式、特性、最低获得等级、性别、闪光限制、事件性格与来源必须组成一条兼容的获得路径。不能把多个互斥活动、世代或进化路线的招式简单取并集。游戏采用的跨世代转移规则需要单独冻结；当前路线表是承载这种约束的核心接口。
4. 困难以上玩家必须通过对应神兽的捕捉剧情门槛，并满足获得来源的门槛。图鉴看见/剧情提到不解锁。捕捉剧情已开放后是否再要求捕获记录，可按来源路线扩展；不能把稀有、6V 或闪光本身判为作弊。
5. 玩家永久 Mega 始终不合法。NPC 永久 Mega 需要疯子难度和明确授权。普通临时形态不能作为持久队伍形态保存；由完整适配器做变身还原。
6. 每次训练师战前检查整个随身队伍；准备实际开战时复核当前队伍与进度。读档、换难度、取出仓库、进化或学习招式后同样需刷新资格。NPC 内容在构建时及入战时复核。

输出区分 ILLEGAL_BUILD、CAPTURE_LOCKED、LEVEL_CAPPED、DATA_UNAVAILABLE 等原因。未知物种、缺少规则表、版本不一致属于数据问题，停止开战并报告，不指责玩家作弊、不自动入库。等级超限提示调整队伍，也不当作作弊。

## 安全入库与恢复

明确非法或捕捉剧情未解锁的成员必须入库后才能继续参战，不放生、不删除。提示可为：“你的 XXX 尚未满足本阶段的参战条件：对应捕捉剧情未开放。请先存入电脑，再调整队伍。”异常努力值或招式应显示实际原因，不统一谴责“不法分子”，更不以未来 bug 威胁玩家。

核心先校验全部成员、容量和身份冲突，再一次性转移；仓库满、资料未知、重复实例 ID 时不修改任何记录。转移保留当前模型全部字段并压紧队伍，不扣物品。完整游戏适配时必须保留真实宝可梦所有字段；当前 OmniMon 是验证模型，不可替代完整存档结构。当前事务仅保证内存内原子性；掉电恢复需要平台存档双槽/日志，在真正 ROM 接入前必须完成。

所有成员被存入后不得进入战斗。平台必须允许访问电脑、治疗/调整队伍并避开视线重复触发；空队恢复流程属于适配验收项。把未解锁宝可梦重新取出也不会绕过下一次检查。仓库允许隔离保存异常记录，不等于允许继续参战。

纯离线 ROM 无法防止修改器同时篡改剧情旗标、数据和校验代码。目标是拒绝明显越权和不自洽队伍，避免破坏流程；不承诺不可破解的反作弊。

## 代码与证据

`core/include/omni/battle_policy.h` 与 `core/src/battle_policy.c`：C99，无渲染、OS、RHH 依赖和动态分配。实现等级、遭遇/重赛决策、独立额度、队伍验证和安全入库。`tests/core/test_battle_policy.c` 使用合成目录，包含三档难度 ×100 基准 ×100 玩家等级的穷举以及多来源互斥、容量不足不修改等边界。

`tools/legality-reference/` 固定 pokemon-showdown 0.11.11 与 pnpm 锁文件，提供开发机参考校验器。它校验显式选定的 Showdown 格式，不替代本项目剧情门槛，不认识原创羁绊。它不进入 GBA ROM。应在内容构建阶段核对合法路径并导出紧凑 C 表。

本轮未实现全物种生产目录、完整跨世代路径编译器、各地捕捉旗标表、NPC 队伍生成器、伤害/效果引擎或 AI；因此不能宣称所有实际宝可梦的合法性已经在 ROM 内得到完整保证。JSON 是规范配置，尚非运行时代码生成源；变更时需同步 C 与测试。
