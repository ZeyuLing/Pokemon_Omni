## 实际质量检查

| 指标 | Gen4 NU 完整分区 | Gen4 OU 前缀抽样 |
|---|---:|---:|
| 完整视角轨迹 | 4,130 | 156 |
| 不同对局 ID | 2,065 | 93 |
| 状态数，含终局 | 131,360 | 5,640 |
| 非终局决策数 | 127,230 | 5,484 |
| 已知动作标签 | 114,276 | 4,918 |
| 缺失动作标签 | 12,954 | 566 |
| 缺失动作占比 | 10.18% | 10.32% |
| 最后状态有胜/负标记 | 4,130 | 156 |
| 超出上游候选编码范围 | 0 | 0 |

两方视角不是两局比赛。OU 的 156 条轨迹也不是 156 局比赛，部分对局只取到了一个视角。前缀顺序抽样仅用于接口检查，不用作代表性成绩或最终测试。

必须保留的限制：

1. 这些是旁观回放的重建状态，**我方初始队伍、道具和配招也可能有推测补全**，不是原始玩家完整私有观察。样本没有字段级真值/推测置信度标记。
2. 本次样本中的 `base_atk/base_def/...` 是种族值，缺少我们需要的完整实际能力值。不能把它们重命名为攻击/防御便认为已经完成适配。
3. `-1` 是缺失动作；终局占位也可能为 `-1`。缺失率按非终局统计，不能把缺失动作默认为随机动作、守住或胜方推荐动作。
4. 上游 `maybe_valid_actions` 只是候选范围，不是完整引擎合法 mask。候选范围检查全部通过不意味着逐动作合法性或精确复演已经验证。
5. 动作索引与我们当前队伍槽位编码并不等价。上游按约定排序招式和替补，必须通过招式/精灵身份映射，不能直接复制整数标签。
6. 旧回放可能采用不同历史规则。NU 与 OU 也有不同合法性约束，不能混在一起并声称都是当前 OU 数据。
7. 聚合统计只给部分边际关系，独立抽样招式、道具和培养会破坏实际配队协同；合法性检查是最低条件，不能替代战术质量检查。

Gen4 OU 聚合统计覆盖 57,675 局底层对局（0/1760 是同一来源的不同权重口径，不能相加）。Gen9 OU 为 574,541，National Dex 为 426,601。**这些是源统计覆盖的比赛数量，不是本次下载的录像数**；更不是“高于该评分阈值的独立对局数”。

## 已验证的环境扩充路径

`probe-prior-teams.cjs` 使用 Gen4 OU 1760 统计，以固定种子采样配置，经 Showdown 校验后组合队伍。此次 268 次尝试得到 256 个不同合法配置，覆盖 45 种精灵、25 种道具、115 个招式、127 种性格/努力值组合，形成 32 支六人队伍。

IV 是生成默认值及校验器归一化值（例如觉醒力量的调整），不是人类原始 IV。拒绝的配置包括遗传招式不兼容、多个觉醒力量类型冲突等；全部保留拒绝原因。

四局 `power` 对战均正常结束（12/17/36/29 回合），逐步重放一致。这证明统计→配置→合法队伍→可结算轨迹的工程路径可用，**不证明这些队伍强，也不证明 agent 学习进步**。

## 根据已有数据调整训练方案

### A. 可立即推进：统计先验驱动的自生成强化学习数据

采用权利明确的规则实现、聚合统计和自有队伍，扩充环境；随后让策略与多种脚本及历史策略对战。新轨迹可记录完整真实的我方数值、准确可见历史、动作请求、提交动作和胜负，弥补公开重建数据的缺口。

优先完成前述五块状态契约（条件、我方、对方、战场记忆、候选动作），再用带记忆的策略/价值网络训练。现有 84 维编码没有因为下载新数据而自动升级，继续大规模训练旧编码不是本轮建议。

边际采样仅作第一种队伍生成器；随后增加角色约束、联合配置和人工自有队伍，避免模型长期面对大量合法但不合理的组合。

### B. 可做研究试验：人类数据预训练 + 离线 RL

当前实测约 11.9 万个已知非终局动作标签足以做小规模接口与学习试验；数量不等于独立样本数或足以训练强 AI。Gen4 NU 全分区适合验证解析/损失，OU 前缀适合验证接口，不承担最终性能结论。

先实现上游序列→统一输入的显式适配，缺失字段用缺失标记，不填成观测真值。第一阶段可用已知动作做行为克隆基线，同时以局终胜负训练价值预测；再比较适用于离线数据的保守策略改进/离线 actor-critic。人类历史数据没有当前策略的行为概率，不能直接冒充当前 PPO rollout。

缺失动作时，动作监督和相应动作条件损失需屏蔽，但历史序列继续保留。不能删除中间状态后把相邻两个已知动作拼成不存在的一步转移。终局结果是标签，不可泄露进当前非终局策略输入。

需要额外审计重建规则：自己的推测配置、敌方已暴露信息、历史反向填充对输入有何影响。能做训练兼容不代表具备真实环境可复演性。

训练/开发先按 battle_id 分组，使双方视角同属一份；正式试验还需按时间与队伍近重复进一步隔离。已经查看的抽样不再承担受保护最终测试角色。既有 protected 数据和结果不用于本轮选择。

### C. 数据源成熟后：离线起点 + 新鲜自博弈提升

研究路径可以从上述离线策略初始化，再在准确、信息隔离的环境中通过对手池采集新轨迹。发布路径则需独立维护其训练数据和权重血缘，不把非商业研究权重自动转为游戏发布权重。

外部自博弈数据是很有价值的后续候选，但本轮未验证样本，也未解决明确数据许可，不能报告为“已可开训”。Gen4 OU 两份主要自博弈负载分别约 6.49 GB、6.97 GB，另有索引；完整人类 Gen4 OU 压缩包约 1.91 GB。先完成适配和小样本学习检查，再决定扩容，避免先下载大包再发现输入不兼容。

多机制方面：已经登记并采集 Gen9 OU/National Dex 的配置统计；它们不等于已经获得 Mega/Z/极巨化等全部机制的行动训练数据。当前实际人类序列样本仍是 Gen4。Omni 多机制仍需明确规则并生成对应轨迹。

## 复现

使用真实 Python 3.12（本机已验证运行时为 Codex 缓存内 Python），不使用 Windows Store 占位命令。下载器为标准库实现，单文件和总量受计划约束，有界重试、缓存校验；不自动下载全量数据，不安装训练框架。

```powershell
python tools/battle-lab/acquire-data.py --plan research/battle-data/2026-10-07/acquisition-lock.json --out build/battle-data/2026-10-07
```

按回执核验已获取 wheel 后，把 `runtime/lz4-4.4.5-cp312-cp312-win_amd64.whl` 解压到本地 `runtime/lz4-4.4.5/`。它是 PyPI 的 BSD-3-Clause Windows CPython 3.12 wheel，SHA-256 固定在计划中；没有修改全局 Python 环境。其他平台需要单独锁定适配 wheel，不能复用此二进制。

```powershell
python -m zipfile -e build/battle-data/2026-10-07/runtime/lz4-4.4.5-cp312-cp312-win_amd64.whl build/battle-data/2026-10-07/runtime/lz4-4.4.5
python tools/battle-lab/inspect-data.py --root build/battle-data/2026-10-07 --lz4-path build/battle-data/2026-10-07/runtime/lz4-4.4.5
node tools/battle-lab/probe-prior-teams.cjs build/battle-data/2026-10-07/stats/gen4ou-1760.json build/battle-data/2026-10-07/prior-probe
python tests/battle-data.test.py
```

`acquisition-plan.json` 保留获取计划，`acquisition-lock.json` 固定所有已采集内容的实际大小和摘要。月度聚合 URL 仍可能被上游重新生成；锁定获取若摘要变化会拒绝该文件，需要登记新数据版本，不能复用旧计数或实验结论。
