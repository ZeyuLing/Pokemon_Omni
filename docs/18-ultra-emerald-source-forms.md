## 表结构与可复现提取

运行 `python -X utf8 tools/extract_ultra_emerald_rom.py`。脚本锁定完整 ROM 哈希，不适用于未经核实的其他 5.8 文件。中文字符表固定到 GoldenCaterpie/pokeemerald-ch 的提交 `c8b4aed68d8ff0af6b2992f54253a0e3cc379bdb`，并校验字符表 SHA-256。

| 数据 | ROM 文件偏移 | 记录大小 |
|---|---:|---:|
| 种族数据 | `0x101D700` | 28 |
| 中文名称 | `0x10442CC` | 11 |
| 正面图 / 背面图 | `0x102E1FC` / `0x1032E44` | 8 |
| 普通 / 异色调色板 | `0x1037A8C` / `0x103C6D4` | 8 |
| 实际特性编号 | `0x17A0000` | 三个 uint16 |
| 特性名称（0–254） | `0x1D03068` | 13 |
| 进化表 | `0x105785C` | 每物种五条，每条 8 |
| 道具表 | `0xFC2C7C` | 44 |

旧种族记录中的特性字节不是运行时的完整特性来源。`0x6B694` 跳转到 `0x1D739E4` 的 Thumb 函数，按 `(species * 3 + slot) * 2` 从新表读取 uint16。提取脚本同时锁定跳转地址、关键机器码、新表指针与中文锚点。

改版特性使用 `ue58_<source_id>` 命名空间；例如 335 的名称仍未解码，明确显示待核实。不会把该编号直接套入官方特性表。共享 C 的官方特性编号字段对此填 0，来源编号保留在源记录中，GBA 文字页仍显示提取到的名称。

`content/source-variants/ultra-emerald-5.8-inventory.json` 保存连续核对区域 1–1385 的原始表记录，包括占位和重复项，不等于 1385 个有效物种。头部指针间距预留 2441 个槽位，但 1385 之后存在被覆盖或无效区域，不能按槽位容量报图鉴数量。201、412、417 的错误精灵及 435–439 的未知图腾改数值项不作为新形态导入。

选中的形态、图像引用、哈希、表偏移、原始名称和进化入边在 `content/source-variants/ultra-emerald-5.8.json`。已有官方 Mega 等记录的源数据仍保留于完整清单；图鉴继续使用已有官方身份与固定参考数据。

## 已核实条件与待接入玩法

进化表中存在：阿尔宙斯 + 光之石 → 1336、阿尔宙斯 + 暗之石 → 1337、洛奇亚 + 光之石 → 1383、凤王 + 火之石 → 1384。目标编号及道具编号均从表提取，道具记录内的 ID 再次核对。没有进化表入口的形态不编造获取方法。

这些是来源版本的规则证据；本作尚未实现这些物种的完整招式、捕获剧情、特性效果、永久形态保持／解除、携带道具与机制额度。因此记录为 `research_only`，不允许通过查看资料获得捕获／解锁进度。不能把“图鉴已有图片和数值”表述成“永久进化战斗系统已完成”。

用户此前确定的规则仍有效：疯子模式的首领永久 Mega 可持有其他道具、不占 Mega 次数、不能再叠加其他机制，玩家无法合法获取。源 ROM 的作弊器与随意获取能力不自动成为 Omni 游戏规则；新神兽形态的获取和剧情门槛另行实现。

## 存储与验证

ROM、解码 PNG、构建 ROM、存档仅本机保存，不提交 Git。提交提取器、来源表、哈希、图鉴生成代码与测试。另一台机器需要用户提供相同哈希的源 ROM 后重新提取。网页服务器仅允许清单中的 PNG URL，不公开源 ROM。
