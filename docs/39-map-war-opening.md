# 原生地图战争开场

2026-09-27。用户要求参考绿宝石固拉多／盖欧卡地图事件的演出方式，将场景扩大并增加宝可梦和人类。本轮撤下静态插画播放，实装可在 GBA ROM 中运行的地图战争过场。参考的是地图上发生交战的形式，未复制绿宝石原事件脚本，也未让固拉多或盖欧卡加入本作战争。

## 当前实装

- 512×320、32×20 格原生像素地图，双岸、河流、上下两处木桥、林带与阵地围栏。地块来自哈希锁定的火红素材，布局由 Omni 编排；没有烘焙宝可梦或人类到背景里。
- **40 个独立单位：22 只宝可梦和 18 名人类**。其中 20 只宝可梦施招，2 只吉利蛋参与救护；人类包含前线训练家、前列支援人员、两名指挥员、救护员和传令员。完整实例表在 `content/opening/battlefield.json`。
- 宝可梦采用豪力、蚊香泳士、皮卡丘、尼多力诺、拉普拉斯、大比鸟和吉利蛋的原版地图精灵。人物采用原版 policeman、cooltrainer_m、nurse、worker_m 行走图。原始朝向帧保留；人类切换行走帧，宝可梦通过位移、浮动、近身冲击、蓄力、招式和受击来演出。没有声称新增了每个物种的专属骨骼／手绘动作帧。
- 双方独立推进；近身交锋、水流、电击、毒针与风系轨迹对应具体施招者和目标。每个攻击周期包含蓄力、释放和恢复；目标出现受击闪烁、击退与尘点。单位分层与纵向排序处理遮挡，空中单位在上层。
- 后撤单位沿已走过的通路脱离前列；救护员与吉利蛋移动到后方接应位置，传令员随后离开原站位。没有死亡事件、胜负结算或确定的人员伤亡。
- 指挥员的命令、前线对桥头的报告和救护通知发生在持续交战中。对白展开不会重置战争时钟；打开跳过确认会同时暂停单位与招式，取消后继续；整段回放不写入存档。

## 演出顺序

1. 镜头从西侧阵地向桥头移动，训练家、宝可梦推进，逐组开始交战。
2. 指挥员要求守桥、后排掩护；镜头继续扫过河中单位和东岸阵线。
3. 转向另一座桥，表现不同单位仍在同时交战，后方开始救护与撤离动作。
4. 前线要求水面部队掩护后撤；镜头回到后方救护与传令区域。
5. “传令员，把伤情送回联盟！”接入既有联盟议事室，由伤情报告进入世界赛方案。

背景音乐沿用已验证的经典《训练家对战》，尾句衔接《希尔弗公司》。本轮没有逐个招式新增来源音效或语音。该段是脚本驱动的地图战争演出，不是可操作的即时战略模式，也不替代未来完整 PvP 战斗规则实现。

## 核心与适配

- `core/include/omni/battlefield.h`、`core/src/battlefield.c`：纯 C 事件单位与姿态采样，处理推进、招式阶段、目标受击、近身冲击及后撤；不包含 GBA 寄存器或像素。
- `adapters/gba/battlefield.c`：原生精灵、深度排序、招式粒子、水面与救护效果；`pallet_game.c` 提供独立演出时钟和镜头，与既有序章同帧合成。
- `tools/build_battlefield.py`：把原版地块及朝向／行走帧编译为素材，校验来源哈希、路线和地形层。源素材记录在 `assets/source/battlefield.json`，下载源图与二进制保持本地。
- `content/opening/battlefield.json`：地图、地形采样、逐单位 ID、队侧、位置、路径、目标和时序。地面单位不能走入河流或障碍；水面单位保持在水域；空中单位允许跨地形。

GBA 绘制属于适配层；未来 3D 前端可以复用时间线、实例身份与动作状态，另做模型和特效。

## 连续性与地理边界

这是既定第一次世界大战末期的无名战场演出。东西两侧只表示镜头中的相对方位，不代表任何地区或组织。河流两端离开画面，不设海岸、地域连接或世界坐标，因此未改动地区地图已知边界。桥梁、林带和阵地是局部舞台布局，不据此补写未定战役、日期、胜负、伤亡和红莲后的政治变迁。

40 个实例全部以 `war-unit-01` 至 `war-unit-40` 登记人物档案，并绑定 `map_battle_unit`；无线电角色另外保留。原画的集体档案已撤下演出绑定。未知生平仍为 `null`，原版游戏小人不冒充已确认的动画人物形象或年龄阶段设计。

旧插画 `assets/opening/world-war-v1.png` 只保留参考，未编译进当前战争舞台。

## 验证与连续录像

```powershell
python tools/build_opening_stages.py
python tools/build_presentation_assets.py
python tools/build_rocket_dialogue.py
./tools/build_pallet.ps1 -ReuseAssets
node tests/war-rom.cjs
python -m pip install --target .cache/war-video-runtime imageio-ffmpeg==0.6.0
python tools/encode_war_video.py
node tests/presentation-rom.cjs
python tests/opening-layout.py
node tests/presentation-browser.cjs
python tools/build_story_bible.py
python tools/build_story_bible.py --check
python tests/story_bible.py
```

`war-rom.cjs` 在实际 ROM 上逐帧读取只读观测信息，验证地形、单位分离、每个攻击者施招、每个目标受击和暂停，不修改 RAM。记录约 39 秒的连续画面与原声，原生画面按最近邻放大为 720×480：`build/pallet/war-playback.mp4`。录制过程采样观测到 38 个单位位移、20 个攻击者、20 个受击目标、最多 6 个同时释放的攻击；两名指挥员保持阵地。

录像导出为约 14.93 fps，仅是降低输出文件采样率，ROM 仍正常逐帧运行。画面证据来自同一次连续运行，不是拼接静态示意图。GBA 真机尚未验收。

本轮同时通过：完整六场／81 节拍的实际 ROM 播放、44 次对白展开与 15 次动作保护检查、七项开场布局检查、标题与旧存档回归、浏览器开场／画册／图鉴入口与存档保护、50 项故事检查和生成器 `--check`。共享核心及 GBA 战场适配分别以 ARM 目标的 `-Wall -Wextra -Werror` 编译通过。已从连续录像抽取每三秒画面检查站位与镜头；证据为 `war-video-review.png`。
