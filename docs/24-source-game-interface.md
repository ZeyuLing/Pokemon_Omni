# 使用来源 ROM 素材重做游戏界面

2026-09-21。纠正上一版以纯色背景、矩形框和大字作为正式战斗／背包展示的问题。此次直接解码用户归档的西班牙火箭队 ROM，使用其界面像素、图块排列与调色板，在实际 GBA ROM 中绘制实时内容。

## 已替换的内容

- 草地和室内战斗场景：保留源背景的横向渐变、地面平台与透视构图；根据野战／室内训练师战选择背景。
- 双方状态框：使用来源像素框，实时显示名称、等级、HP、麻痹与玩家经验条；动态血条按当前 HP 绘制，不把整张静态截图当作游戏界面。
- 底部三类框：提示框、四项指令框、招式／PP 分栏框均来自原始战斗 tilemap。恢复“战斗、背包、宝可梦、逃跑”选择，进入招式后可以返回。
- 背包：原有左右分栏底图、绿色背包的五个口袋帧、伤药／精灵球／返回图标与各自调色板。口袋按道具、精灵球、技能机器、树果、重要物品排列；未接入道具的技能机器和树果袋显示为空袋。包裹交还后从重要物品袋消失。普通与战斗背包均不显示金钱栏或额外页脚。
- 通用对话和选择面板：使用来源窗口九宫格边框；文字使用已有 12 像素中文字库和紧凑数字，减少原来 16 像素大字导致的拥挤。
- 战斗中的换人列表提供明确选人；HP 从当前战斗对象读取，不展示入战前的旧 HP。原有 L 投球、R 快速轮换仍保留作快捷操作。

队伍详情、训练家卡片、商店和标题的完整构图还没有替换成来源游戏的对应界面；它们使用现有结构及统一文字／窗口样式。地图主角仍是占位像素。此次不声称全游戏美术、动画或音效已完成，也未扩大共享战斗引擎的物种／招式覆盖。

## 来源与复现

输入为 `assets/imported/rocket-user/rocket-user-modifier.gba`，SHA-256 `033235cdd389c4c8cb1aa6d68a93954a55fd681c92a1a554ebc63431117b4eaf`。本次使用这一份来源的视觉套件，未混称为究极绿宝石 5.8 的 UI。

定位时以 pret/pokeemerald 的 `5eff78649e7170a877b961ef0b3da13b81a16038` 为结构参考，将 PNG 按上游图块顺序编码，与两份用户 ROM 的解压内容比对。多项界面框、背包背景和道具图在两份 ROM 中均存在相同内容；最终构建只读取火箭队 ROM。草地和室内背景则从火箭队自己的场景表及对应调色板读取，不用上游默认配色覆盖。

另外在 mGBA 中载入来源 ROM，以普通菜单按键实际打开背包作视觉对照，确认紫蓝横纹、绿色背包、淡黄色列表和左下说明框确为该版本的背包配色与结构。参考截图保存在本地 `.cache/rocket-bag-reference.png`；本作的道具、数量、正文和操作仍由自身运行时绘制。

源 ROM 场景表位置为 `0x5a6368`，每项五个指针。单打信息框必须按 64×64／64×32 分块顺序重排。战斗 tilemap 的提示、指令与招式布局分别在 y=112、272、432 处，按 240×48 提取；没有凭感觉临摹原边框。当前共有 30 个来源数据块，组合为 23 个 GBA 适配资源，327,552 字节。

`assets/source/game-ui.json` 保存 ROM 身份、每块偏移、编码、压缩前后哈希、输出尺寸与像素哈希。`tools/build_game_ui_assets.py` 锁定完整 ROM 哈希，随后检查各块记录；输入错误会停止，不静默退回临时色块。

```powershell
./tools/build_pallet.ps1
node tests/pallet-smoke.cjs
node tests/bag-layout.cjs
python -X utf8 tests/test_game_ui.py
node tools/serve_pokedex.cjs
node tests/pallet-browser.cjs
```

构建会自动调用界面提取器。另一台机器需要相同的本地来源 ROM。源 ROM、解码 PNG、像素数据包、生成头文件及最终游戏 ROM 都留在忽略目录，不提交 Git。GBA 显示适配使用这些资源；共享 C 剧情、队伍、战斗规则与存档格式未改变。已有冒险可继续读取，不要求新建存档才能看到新界面。

## 验证

实际 mGBA 正常按键路线包含：图鉴启动、伙伴领取、背包五个口袋、战斗主指令、招式与返回、战斗背包投球、拒绝捕获训练师宝可梦、换人列表、开场任务、购物、保存／继续、旧存档迁移和坏槽回退。

`tests/test_game_ui.py` 检查图块排序／翻转、30 块来源数据哈希和全部输出像素包，并逐像素核对实际模拟器截图中无文字／角色遮挡的草地、室内与背包区域确实等于提取资源。也检查背包、箭头、返回图标、五个指示灯的实际帧缓冲位置，以及列表空白区没有被任何颜色的金钱／提示文字占用（含战斗背包）。

浏览器另检查存档导入导出、音效开关、键盘／触屏入口及三种视口宽度。真机与全套战斗动画仍未验证。截图和对应 ROM 哈希位于本地 `build/pallet/`，不把旧截图当作新构建结果。

本轮最终构建：27 MiB，SHA-256 `e5cbdbc076e757d8af16109b38af42b37cc365e4e828f8fd0234c4d44e733f26`，GBA 头校验通过。mGBA 路线 446 次正常按键、源像素与排版验证六项测试、浏览器检查均通过；最后截图与该 ROM 对应。

## 基础界面以来源实机画面为准

不能只复用底图，再凭感觉填充信息。用户明确要求基础 UI 对齐已有作品：背包不应出现金钱，即使移到“安全区域”仍然不符合来源布局。本项目以归档火箭队 2.1 的运行画面为视觉基准，以锁定版本的上游代码为布局定位依据；尚未实际核实的界面不能标记为完全对齐。

背包已核对的坐标（240×160 像素）：

| 元素 | 布局依据与实现 |
| --- | --- |
| 列表 | `item_menu.c` 的窗口 `(112,16)`，名称偏移 `(8,1)`，即 `(120,17)`，16 像素行距 |
| 数量 | 同行，右边界为窗口 x + 119，即 231；重要物品无数量 |
| 关闭行 | 来源中文“合上背包”，紧接最后一项；空袋占首行 |
| 光标 | 实际截图的黑色实心箭头，x=113，字行 y+3，5×9 像素 |
| 背包图 | `item_menu_icons.c` 中心 `(68,66)`，64×64 图对应左上 `(36,34)` |
| 左右箭头 | 来源 16×16 红色精灵，左上 `(20,8)` 与 `(92,8)`；当前采用静止帧 |
| 口袋指示灯 | `DrawPocketIndicatorSquare` 的图块 0x17/0x2b，x=40+8×口袋序号、y=24 |
| 道具／返回图标 | 24×24 来源图，左上 `(8,72)`；选中关闭时显示返回箭头 |
| 左下说明 | 窗口 `(0,104)` + `(3,1)`，即 `(3,105)`；关闭显示“回到／主界面。” |
| 列表下方 | 保持来源空白，无金钱、战斗状态或键位说明 |

中文文字仍使用项目的 12 像素字库，与来源字形及阴影有差异；左右箭头摆动、背包切换动画和完整道具操作菜单尚未移植，因此不能称为像素级完整复刻。当前并排核对图为 `build/pallet/bag-reference-comparison.png`，左为来源实际画面，右为本作实际 ROM。

对战状态框依据 `battle_interface.c` 单打原点 `(44,30)/(158,88)` 与初始 OAM 中心偏移 `(-32,-16)` 放置。名称留在框内，等级和 HP 数字右对齐。经验条使用来源 8×8 图块组成 64 像素条，位置为 `(158,104)`。这属于已核实结构与当前游戏画面的布局修正，尚未取得来源同场战斗的逐像素对照；战斗字体、动态 HP 条以及队伍选择页面仍有移植工作。

`tests/bag-layout.cjs` 使用独立 SRAM 测试数据，不写入用户浏览器存档。它通过正常按键渲染 0、9、99、999 库存，包含五个口袋、博士包裹长名称、空袋、关闭选择及左右循环切换，共 31 张画面。测试存档余额设为 999999，以确认大额余额也不会出现在背包中。测试先确认 SRAM 已加载且实际进入背包，再检查实际帧缓冲。

新增素材时，实际渲染检查发现 Zig 汇编缓存未跟踪 `.incbin` 文件变动，可能把旧像素包与新偏移组合。生成器现将素材包 SHA-256 写入汇编源，素材变更会使汇编缓存失效；新增的图标逐像素检查覆盖了此问题。

## 2026-09-26：开场对白的真实来源字体与 field dialogue

开场的通用九宫格、细字库、独立蓝色姓名栏与 A 提示已替换为归档火箭队的绿色 field dialogue、原 ROM 汉字和标点、灰色笔画及浅色阴影、正文姓名前缀与红色续页箭头。正文 `(16,121)`，14 像素行距，窗口 `(0,112,240,48)`；以来源正常开机的运行画面逐像素验证，再比较本作全部实际对白帧。

提取器为 `tools/build_rocket_dialogue.py`，ROM 身份、字库及 UI 偏移记录在 `assets/source/rocket-dialogue.json`。详见 [开场实现与验证](36-playable-opening-and-cast.md)。这里只更新开场的字体与布局结论；背包、战斗和普通探索仍使用旧字库的限制继续成立。
