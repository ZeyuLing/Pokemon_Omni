# 图鉴浏览规则与便利功能规划

更新：2026-09-20。

## 已实现：物种主列表与形态附录

- 主列表先显示 1,025 个基础条目，按全国编号排列；接着是 538 个其他形态条目，同组沿用全国编号次序。
- 普通极巨化属于战斗状态，不作为独立图鉴形态：主列表、筛选结果、同物种形态、详情 L/R 导航和收集计数均排除。
- Mega、超极巨化、地区形态等仍可查阅；查找某物种时，先出现基础条目，再出现其其他形态。
- 当前可浏览 1,563 条，其中 23 条火箭队羁绊资料仍为研究条目；这些计数不代表全部数据或玩法已审定。
- 原始资料库仍保留 2,384 条稳定 ID，包含 821 条普通极巨化参考记录。它们用于兼容旧记录和机制说明，不计入图鉴完成率。不会因这次浏览规则变更重置存档。
- 网页旧极巨化链接转到对应形态；已有资格参考的普通形态详情仍可查看 HP 计算。此参考范围不等于 Omni 战斗规则已批准。
- 同一筛选结果内用 L/R 切换宝可梦；从形态页跳到筛选结果外的形态时，下一次 L/R 回到筛选结果首项。

规则位于共享 C 核心；GBA 与网页使用相同查询结果。图鉴默认顺序是本项目的产品决定，不冒充所有历代作品共同采用的布局。

## 建议的游戏内便利功能（尚未实现）

优先解决找不到、看不懂、记不住，再接入依赖完整世界或战斗系统的功能。保持 GBA 的列表、详情、A/B 和 SELECT 页面目录，不引入桌面式多窗口。

| 优先级 | 功能 | 玩家得到什么 | 条件与边界 |
| --- | --- | --- | --- |
| 第一批 | 收藏、最近浏览、返回位置 | 把想培养的形态加入短清单；返回时保留筛选、页码和选中条目 | 使用稳定 ID；旧存档迁移；收藏不等于捕获或解锁 |
| 第一批 | 中文拼音／首字母搜索与组合筛选 | 编号、中文名、拼音首字母；可按属性、特性、招式寻找候选 | GBA 使用选择面板和有限字符键盘；招式来源与四招组合合法性分开 |
| 第一批 | 双形态比较 | 对照普通与 Mega 的属性、特性、种族值差值、携带限制、机制额度 | GBA 两栏或逐项切换；实战 HP 与种族值分开 |
| 第二批 | 培养目标清单 | 选择参考方案，列出招式、性格、努力值、道具，以及尚缺条件 | 现有网页有 987 套参考方案，覆盖 324 个确切形态；不把缺失方案称为最优 |
| 第二批 | 进化／变形条件检查 | 选择队伍中的个体后，显示等级、道具、亲密度等哪些已满足 | 读取共享剧情与背包状态；羁绊专属条件须先审定 |
| 世界接入后 | 捕获与道具指引 | 显示已知地点、时段、天气、剧情前置，并加入探索目标 | 目前仅初始伙伴获取已接入；未配置标为未知，不能借用别的游戏地点冒充本作地点 |
| 战斗核心接入后 | 队伍短板分析 | 防守弱点、抗性、免疫、进攻覆盖，以及替换候选 | 第一版按属性表算；特性、道具、天气与机制必须由本作规则引擎计算 |
| 规则接入后 | 参战资格预检查 | 战前提示神兽捕获剧情、等级上限、EV 总和与四招组合问题，并给出调整办法 | 与真正开战检查使用同一 C 接口；未知状态不能伪称合法或作弊；不查看 NPC 隐藏选择 |

网页已有收藏、四形态比较、种族值排序、招式筛选与培养方案；它们尚未因此自动成为游戏内功能。上表是游戏内计划，不是已完成清单。

## 可复用的实现边界

新增 C 模块建议分别为 `dex_workspace`（稳定 ID 收藏、历史和返回位置）、`dex_compare`（只读差异）、`dex_goal`（培养目标与缺项）。索引与资料表离线生成，GBA 不运行全量网络资料解析。

`dex_goal` 通过只读玩家／剧情上下文调用进化、获取与合法性规则；图鉴不自行复制一份战斗判定。GBA 负责像素布局与按键，网页负责 DOM，未来 3D 适配器也读取相同结果。

测试重点是旧存档不丢记录、查询与导航一致、缺资料的明确状态、规则检查与真正开战一致，以及 240×160 界面可读性。
