# 对战训练基础：第一阶段（2026-10-06）

本轮把“可复现模拟器 → 双方独立观察 → 基线决策 → 评测／轨迹”做成了可执行闭环。它是开发机参考训练后端，**还没有训练神经网络，没有实现信念推断、博弈搜索、策略群体或 GBA 推理**。

这段描述为第一阶段历史记录。2026-10-06 后续已完成实际网络训练与首轮自博弈，最新状态见 [策略／价值学习记录](battle-learning-v2.md)。

## 已实现

入口：[`tools/battle-lab/README.md`](../tools/battle-lab/README.md)。依赖复用原有 Showdown 0.11.11 锁文件；冻结 `gen4ou`，不伪装为 Omni 全机制规则。选择这个环境是为了先验证训练基础设施，而非冻结游戏最终赛制。

- 无画面完整参考对局，队伍合法性校验，分玩家消息渠道和递归只读观察。
- 公开动作集合、双方动作提交屏障、濒死替换和急速折返请求；隐藏磁力拒绝换人时，对手的待结算指令保持私有。
- 环境／策略独立随机流；快照、恢复、分叉；动作日志与逐观察摘要重放。
- 随机与基础威力启发式基线，三套合成六人阵容，四局交换队伍／位置的评测块。
- 终局与截断分开报告，完成块 bootstrap，源版本清单与可选逐选手 JSONL 轨迹。
- JSONL 标准输入输出接口，可供后续 Python/PyTorch 训练编排器使用。

Node 后端只负责研究与参考。Omni 的正式战斗规则、与 GBA／宿主共用的结算和未来部署推理仍应在可移植 C 核心中落实；当前没有将 Showdown 或其全知状态接入 ROM AI。

## 实际验证

本机 Node.js 24.19.0：

```powershell
node --test tests/battle-lab.test.cjs
node tools/legality-reference/test.cjs
node tools/battle-lab/cli.cjs evaluate --blocks 120 --out build/battle-lab/validation-20261006
node tools/battle-lab/cli.cjs evaluate --blocks 3 --agents power,power --trajectories --out build/battle-lab/trajectories-20261006
node tools/battle-lab/cli.cjs replay --file build/battle-lab/validation-20261006/b00119-l3.replay.json
```

18 项训练环境测试及原有 12 项合法性参考检查通过。测试包括隐藏配置不变性、指令提交顺序独立性、环境 RNG 独立、公开 HP 精度、快照独立、锁定指令与隐藏磁力、单方换人、PP 耗尽后的挣扎、真实平局、终局奖励、截断、日志篡改和 JSONL 错误恢复。

| 运行 | 对局数 | 完成／截断 | 观察结果 |
|---|---:|---|---|
| power 对 random，120 个交换块 | 480 | 480／0 | power 480 胜；每局都另行重放并核对全部观察摘要 |
| power 对 power，3 个交换块，导出轨迹 | 12 | 12／0 | 候选位置 5 胜 7 负；全部重放一致 |

第一组耗时约 14.31 秒，即约 33.55 局／秒、814 决策帧／秒；包含独立重放、合法性校验、哈希与写盘。第二组约 0.51 秒；小样本计时仅作开发参考。CPU 并发负载、缓存和磁盘均可能改变测量结果，未测得大规模训练吞吐。

**480 胜只说明简单攻击策略能击败当前随机基线，不证明高手水平。**合成阵容规模小且不独立于开发；没有强搜索对手、真人、未见配队或跨赛制验证。第一组得分无块间变化，bootstrap 区间明确留空，不输出伪精确的 `[1,1]`。第二组只有三个块，同样不适合推断稳定强度。

输出保存在忽略的 `build/battle-lab/`；Git 只保存可复现代码、测试、合成阵容与本记录。本次没有改动或验证真实 GBA 对战画面。

## 后续工程顺序

1. 增加有来源的训练／独立评测队伍和强搜索基线；按队伍家族、对手和时间切分数据，避免开发集当测试集。
2. 为 Python 训练器实现固定特征编码与动作映射，建立可复现的模仿学习／离线价值学习基线。正确排除拒绝动作与等待帧，分别处理终局和截断。
3. 实现有历史记忆的策略／价值网络，加入隐藏配置的概率推断；训练信息只能来自该选手视角。
4. 增加历史策略池、自博弈采样、完整胜率矩阵及 checkpoint 晋级规则。
5. 在有可靠策略和价值基线之后，比较同时行动的信息集搜索与纯策略收益；不能把已提供的全知快照分叉当成公平搜索。
6. 冻结 Omni 规则，补全共享 C 结算并做差分验证，随后再评估蒸馏与 GBA 预算。
